Generating PDF Invoices in Node.js:
A Complete 2026 Walkthrough

Sep 2026 · 10 min read · pdfsnap

Every SaaS, marketplace, and freelance platform eventually needs to generate PDF invoices. The implementation looks simple until you're three hours in: fonts rendering wrong, tables breaking across pages, Puppeteer refusing to install on Lambda. This is the guide that gets you there cleanly.

We'll cover the HTML invoice template, the CSS that makes it print-ready, the three approaches to PDF generation in Node.js (and when each makes sense), and a production Express endpoint you can drop straight into your app.

Step 1: Build the invoice HTML template

The cleanest approach is to keep your invoice as an HTML template with placeholder variables. This gives you full CSS control, easy maintenance, and the ability to preview in a browser before generating the PDF.

invoice-template.js
function buildInvoiceHtml(invoice) {
  const { number, date, dueDate, company, client, items, notes } = invoice;

  const subtotal = items.reduce((sum, item) => sum + item.quantity * item.unitPrice, 0);
  const tax = subtotal * 0.1; // 10% tax — adjust to your jurisdiction
  const total = subtotal + tax;

  const rows = items.map(item => `
    <tr>
      <td>${item.description}</td>
      <td class="num">${item.quantity}</td>
      <td class="num">$${item.unitPrice.toFixed(2)}</td>
      <td class="num">$${(item.quantity * item.unitPrice).toFixed(2)}</td>
    </tr>
  `).join('');

  return `<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8" />
  <style>
    * { box-sizing: border-box; margin: 0; padding: 0; }
    body {
      font-family: -apple-system, 'Helvetica Neue', Arial, sans-serif;
      font-size: 14px;
      color: #111;
      background: #fff;
      padding: 48px 56px;
    }
    .header { display: flex; justify-content: space-between; margin-bottom: 48px; }
    .company-name { font-size: 22px; font-weight: 700; margin-bottom: 4px; }
    .label { font-size: 11px; text-transform: uppercase; letter-spacing: 0.06em; color: #888; }
    .invoice-title { font-size: 32px; font-weight: 800; text-align: right; color: #111; }
    .invoice-meta { text-align: right; color: #555; margin-top: 6px; line-height: 1.8; }
    .parties { display: flex; justify-content: space-between; margin-bottom: 40px; }
    .party-block p { color: #444; line-height: 1.7; }
    table { width: 100%; border-collapse: collapse; margin-bottom: 24px; }
    th {
      background: #f4f4f4;
      font-size: 11px; text-transform: uppercase; letter-spacing: 0.06em;
      padding: 10px 12px; text-align: left; color: #555;
      border-bottom: 2px solid #e0e0e0;
    }
    td { padding: 12px 12px; border-bottom: 1px solid #e8e8e8; color: #333; }
    .num { text-align: right; font-variant-numeric: tabular-nums; }
    .totals { margin-left: auto; width: 280px; }
    .totals-row { display: flex; justify-content: space-between; padding: 8px 0; color: #555; }

  </style>

      <div class="invoice-meta">
        <div><span class="label">Invoice #</span> ${number}</div>
        <div><span class="label">Date</span> ${date}</div>
        <div><span class="label">Due</span> ${dueDate}</div>
      </div>
    </div>
  </div>

  <div class="parties">
    <div class="party-block">
      <div class="label" style="margin-bottom:8px">Bill to</div>
      <strong>${client.name}</strong>

    </div>
  </div>

  <table>
    <thead>
      <tr>
        <th>Description</th>

        <th class="num">Unit Price</th>

    <div class="totals-row"><span>Subtotal</span><span>$${subtotal.toFixed(2)}</span></div>

    <div class="totals-row total"><span>Total Due</span><span>$${total.toFixed(2)}</span></div>

}

module.exports = { buildInvoiceHtml };
Design tip

Use system fonts (-apple-system, Helvetica Neue, Arial) in your invoice HTML — they render consistently across Chrome versions without any font loading step. If you need a custom font, embed it as a base64 data URI in a @font-face rule.

Step 2: Choose how to generate the PDF

There are three real approaches. The right one depends on where your Node.js code runs.

Approach A: Puppeteer (self-managed Chrome)

Puppeteer launches a full Chrome browser, loads your HTML, and calls page.pdf(). It gives you pixel-perfect rendering and works well on a long-lived server:

generate-invoice-puppeteer.js
const puppeteer = require('puppeteer');
const { buildInvoiceHtml } = require('./invoice-template');

async function generateInvoicePdf(invoiceData) {
  const html = buildInvoiceHtml(invoiceData);

  const browser = await puppeteer.launch({
    args: ['--no-sandbox', '--disable-setuid-sandbox'],
  });
  const page = await browser.newPage();
  await page.setContent(html, { waitUntil: 'networkidle0' });
  const pdf = await page.pdf({
    format: 'A4',
    printBackground: true,
    margin: { top: '0', bottom: '0', left: '0', right: '0' },
  });
  await browser.close();
  return pdf; // Buffer
}

The catch: Puppeteer bundles a ~300MB Chromium binary. AWS Lambda has a 250MB zip limit. Vercel serverless functions cap at 250MB compressed. If you're on any serverless platform, Puppeteer doesn't fit.

Approach B: PDFKit or pdf-lib (pure JavaScript)

Libraries like pdfkit let you build PDFs programmatically in pure Node.js — no browser required, tiny footprint. The tradeoff: you describe the layout in code rather than HTML, which means your invoice template becomes 200 lines of coordinate-based drawing instructions:

generate-invoice-pdfkit.js
const PDFDocument = require('pdfkit');

function generateInvoicePdf(invoiceData) {
  const doc = new PDFDocument({ margin: 50 });
  const chunks = [];
  doc.on('data', chunk => chunks.push(chunk));

  // Header
  doc.fontSize(22).font('Helvetica-Bold').text(invoiceData.company.name, 50, 50);
  doc.fontSize(32).font('Helvetica-Bold').text('INVOICE', { align: 'right' });

  // Line items — manual coordinate math
  let y = 200;
  invoiceData.items.forEach(item => {
    doc.fontSize(12).font('Helvetica').text(item.description, 50, y);
    doc.text(`$${(item.quantity * item.unitPrice).toFixed(2)}`, 0, y, { align: 'right' });
    y += 24;
  });

  doc.end();
  return new Promise(resolve => {
    doc.on('end', () => resolve(Buffer.concat(chunks)));
  });
}

This works — but maintaining pixel-level alignment, handling page breaks, and matching your brand design is a slog. Any change to your invoice layout requires rewriting coordinate math.

Approach C: REST API (pdfsnap) — recommended for serverless

You POST the HTML to the pdfsnap API and get a PDF buffer back. Your app stays thin: no browser binary, no coordinate math, no process management. Works identically from Lambda, Vercel, Cloudflare Workers, or a plain Express server.

generate-invoice-api.js
const { buildInvoiceHtml } = require('./invoice-template');

async function generateInvoicePdf(invoiceData) {
  const html = buildInvoiceHtml(invoiceData);

  const res = await fetch('https://api.pdfsnap.dev/v1/pdf', {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${process.env.PDFSNAP_API_KEY}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      html,
      options: {
        format: 'A4',
        printBackground: true,
      },
    }),
  });

  if (!res.ok) {
    const err = await res.json();
    throw new Error(`PDF generation failed: ${err.error.message}`);
  }

  return Buffer.from(await res.arrayBuffer());
}

module.exports = { generateInvoicePdf };

Step 3: Wire it into an Express endpoint

Here's a complete Express route that accepts invoice data in the request body, generates the PDF, and streams it back to the client:

routes/invoices.js
const express = require('express');
const router = express.Router();
const { generateInvoicePdf } = require('../lib/generate-invoice-api');

// POST /api/invoices/generate
// Body: { number, date, dueDate, company, client, items, notes }
router.post('/generate', async (req, res) => {
  try {
    const invoiceData = req.body;

    // Basic validation
    if (!invoiceData.number || !invoiceData.items?.length) {
      return res.status(400).json({ error: 'Invoice number and at least one item are required.' });
    }

    const pdfBuffer = await generateInvoicePdf(invoiceData);

    res.set({
      'Content-Type': 'application/pdf',
      'Content-Disposition': `attachment; filename="invoice-${invoiceData.number}.pdf"`,
      'Content-Length': pdfBuffer.length,
    });

    res.send(pdfBuffer);
  } catch (err) {
    console.error('Invoice generation failed:', err);
    res.status(500).json({ error: 'Failed to generate invoice PDF.' });
  }
});

module.exports = router;

Step 4: Email the invoice as an attachment

Once you have the PDF buffer, attaching it to an email with Nodemailer takes two extra lines:

email-invoice.js
const nodemailer = require('nodemailer');
const { generateInvoicePdf } = require('./lib/generate-invoice-api');

const transporter = nodemailer.createTransport({
  host: process.env.SMTP_HOST,
  port: 587,
  auth: {
    user: process.env.SMTP_USER,
    pass: process.env.SMTP_PASS,
  },
});

async function emailInvoice(invoiceData, recipientEmail) {
  const pdfBuffer = await generateInvoicePdf(invoiceData);

  await transporter.sendMail({
    from: 'billing@yourapp.com',
    to: recipientEmail,
    subject: `Invoice ${invoiceData.number} from ${invoiceData.company.name}`,
    text: `Please find your invoice attached. Total due: $${calculateTotal(invoiceData.items)}.`,
    attachments: [
      {
        filename: `invoice-${invoiceData.number}.pdf`,
        content: pdfBuffer,
        contentType: 'application/pdf',
      },
    ],
  });
}

function calculateTotal(items) {
  const subtotal = items.reduce((s, i) => s + i.quantity * i.unitPrice, 0);
  return (subtotal * 1.1).toFixed(2); // including 10% tax
}

When to use each approach

Use Puppeteer if you're on a long-lived server with controlled memory and your invoice volume is very high (100k+/month where API cost matters).

Use PDFKit if you need a purely offline solution with zero external dependencies and are willing to maintain coordinate-based layout code.

Use pdfsnap API if:

  • You're on serverless (Lambda, Vercel, Cloudflare Workers)
  • You want to maintain your invoice as HTML/CSS (the natural format for web developers)
  • You want to ship the feature today rather than debug Puppeteer deployment issues
  • Invoice volume is under ~50k/month
Page breaks: For multi-page invoices, add page-break-inside: avoid to your line items and page-break-before: always before summary sections. Chrome respects these CSS properties when rendering to PDF, so the same rules work with both Puppeteer and pdfsnap.

Common pitfalls

  • HTML entities in template strings: If you're building HTML via template literals, be careful with characters like < and & in invoice data — escape them with a small utility function before interpolating into the HTML.
  • Decimal precision: Always use .toFixed(2) for currency display. JavaScript floating point will give you 59.999999999 without it.
  • Timezone in dates: Invoice dates should be explicit — store and display them in UTC or a named timezone. Don't let new Date().toLocaleDateString() decide the format based on server locale.
  • PDF filename in Content-Disposition: Always set this header when streaming PDFs — without it, browsers will display the PDF inline rather than prompting a download.
