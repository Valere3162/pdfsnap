How to Convert HTML to PDF in Node.js
(Without wkhtmltopdf)

Sep 2026 · 8 min read · pdfsnap

wkhtmltopdf used to be the go-to answer for "HTML to PDF in Node.js" — a shell exec away. Then it went unmaintained, accumulated unpatched CVEs, and its QtWebKit rendering engine fell years behind modern CSS. In 2026, you need a different answer.

There are three real options. Each has a different cost profile, and the right one depends on where your Node.js code actually runs.

Option 1: Puppeteer (self-managed Chromium)

Puppeteer is the obvious first choice — it ships with its own Chromium build and exposes page.pdf(). For local scripts and CI jobs it works great:

generate-pdf.js
const puppeteer = require('puppeteer');

async function htmlToPdf(html) {
  const browser = await puppeteer.launch();
  const page = await browser.newPage();
  await page.setContent(html, { waitUntil: 'networkidle0' });
  const pdf = await page.pdf({
    format: 'A4',
    printBackground: true,
    margin: { top: '20mm', bottom: '20mm', left: '15mm', right: '15mm' }
  });
  await browser.close();
  return pdf; // Buffer
}

The problem shows up when you try to run this in production:

  • Bundle size: Puppeteer pulls in a full Chromium binary — around 300MB. Lambda's zip limit is 250MB (unzipped: 512MB). Vercel serverless functions cap at 250MB compressed. You'll hit the limit.
  • Cold starts: Launching a browser process adds 2–8 seconds to a cold start. For a request-per-render architecture, this compounds at load.
  • Concurrency: Each concurrent PDF needs its own browser tab (or browser instance). Under load, you're managing a process pool — or you hit memory limits and get crashes.
  • Crashes: Headless Chrome is not a stable daemon. OOM kills happen. "Unknown browser error" happens. You need retries, timeouts, and a process monitor.
Verdict

Good for scripts, small internal tools, or long-running servers with careful process management. Not suitable for serverless functions (Lambda, Vercel, Cloudflare Workers) or high-concurrency endpoints.

Option 2: Playwright

Playwright's API is nicer than Puppeteer's, and page.pdf() is nearly identical:

generate-pdf.js
const { chromium } = require('playwright');

async function htmlToPdf(html) {
  const browser = await chromium.launch();
  const page = await browser.newPage();
  await page.setContent(html);
  const pdf = await page.pdf({ format: 'A4', printBackground: true });
  await browser.close();
  return pdf;
}

The trade-offs are the same as Puppeteer — Playwright's Chromium is just as large and just as expensive to launch. The main difference is better ergonomics and a slightly more stable process model. If you're already using Playwright for testing, it's an easy reach. But the deployment constraints are identical.

Note on @sparticuz/chromium: There's a stripped-down Chromium package designed for AWS Lambda that cuts the binary to ~50MB. It works, but it requires matching the exact Lambda runtime layer, breaks regularly across Node.js major versions, and has rendering differences from full Chrome. A reasonable workaround — not a clean solution.

Option 3: A REST API (pdfsnap)

Instead of running Chromium inside your Node.js process, you POST the HTML to an endpoint and get a PDF back. Your app doesn't touch a browser. The PDF generation scales separately, you pay per render, and there's nothing to install or manage.

generate-pdf.js
const fs = require('fs');

async function htmlToPdf(html, outputPath) {
  const res = await fetch('https://api.pdfsnap.dev/v1/pdf', {
    method: 'POST',
    headers: {
      'Authorization': 'Bearer YOUR_API_KEY',
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({ html }),
  });

  if (!res.ok) {
    const err = await res.json();
    throw new Error(`PDF generation failed: ${err.error.message}`);
  }

  const buffer = await res.arrayBuffer();
  fs.writeFileSync(outputPath, Buffer.from(buffer));
}

// Works inside a Lambda, Vercel function, Cloudflare Worker, or anywhere else
await htmlToPdf('
Invoice #1001
', 'invoice.pdf');

The approach works the same from any Node.js environment — Express, Next.js API routes, Vercel serverless, AWS Lambda, a plain script. There's nothing to install beyond node-fetch (or native fetch in Node 18+). No 300MB binaries, no cold start browser launch, no process crashes to handle.

Streaming large PDFs

For large documents you can stream the response directly to disk or an S3 upload, without buffering the whole thing in memory:

stream-pdf.js
const { pipeline } = require('stream/promises');
const { Writable } = require('stream');

async function htmlToPdfStream(html) {
  const res = await fetch('https://api.pdfsnap.dev/v1/pdf', {
    method: 'POST',
    headers: {
      'Authorization': 'Bearer YOUR_API_KEY',
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({ html }),
  });

  if (!res.ok) throw new Error('PDF generation failed');

  // Stream directly to a file
  const fileStream = fs.createWriteStream('./output.pdf');
  await pipeline(res.body, Writable.fromWeb(fileStream));
}

When to use each

Use Puppeteer/Playwright if:

  • You're running on a long-lived server with controlled memory (not serverless)
  • You need to render PDFs from private internal URLs that can't be sent to an API
  • You have high-volume batch jobs where per-render API cost exceeds a process manager cost

Use a REST API if:

  • You're on serverless infrastructure (Lambda, Vercel, Cloudflare Workers, Deno Deploy)
  • You want zero-ops: no binary updates, no OOM monitoring, no crash handling
  • You want to ship a PDF feature in 15 minutes, not 15 hours
  • Render volume is low-to-medium (under ~50k/month)

Migration from wkhtmltopdf

If you're currently shelling out to wkhtmltopdf, migration to a REST API is one of the simpler rewrites you'll do:

before.js (wkhtmltopdf)
const { exec } = require('child_process');

function htmlToPdf(html, output) {
  return new Promise((resolve, reject) => {
    const proc = exec(`wkhtmltopdf - ${output}`, (err) => {
      if (err) reject(err); else resolve();
    });
    proc.stdin.write(html);
    proc.stdin.end();
  });
}
after.js (pdfsnap API)
async function htmlToPdf(html, output) {
  const res = await fetch('https://api.pdfsnap.dev/v1/pdf', {
    method: 'POST',
    headers: {
      'Authorization': 'Bearer YOUR_API_KEY',
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({ html }),
  });
  if (!res.ok) throw new Error('PDF generation failed');
  const buf = Buffer.from(await res.arrayBuffer());
  require('fs').writeFileSync(output, buf);
}

The interface is identical. Drop-in replacement minus the shell dependency and Chromium binary.
