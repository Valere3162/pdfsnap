How to Generate PDF Reports from API Data

Sep 2026 · 7 min read · pdfsnap

Generating a PDF from API data is a three-step pipeline: fetch the JSON, render it into HTML, then convert that HTML to a PDF. The first two steps are standard backend work. The third step is where most developers hit a wall — browser binaries, system libraries, serverless packaging nightmares.

This guide shows the full pattern using pdfsnap as the rendering step. You bring the data and the template; pdfsnap handles the headless Chrome conversion on the other end. The result is a REST-first, zero-dependency PDF pipeline that runs anywhere Node.js or Python runs.

The Pattern

Every API-to-PDF flow looks like this:

  1. Fetch data from your API (JSON)
  2. Render HTML using a template string or template engine
  3. POST the HTML to https://api.pdfsnap.dev/pdf
  4. Receive PDF bytes — stream to the client, save to disk, or upload to storage

That's it. No Puppeteer, no Docker, no lambda layers.

When to use HTML POST vs URL mode: POST your HTML string when the data comes from an internal API or database and shouldn't be publicly accessible. Use URL mode ("url": "...") when the page is already rendered and publicly reachable (e.g., a report at https://app.example.com/reports/123 behind a shared token).

Node.js: Full Working Example

1
Fetch data from your API
report.js
// Fetch the data from your internal API (or any REST endpoint)
const apiRes = await fetch('https://api.example.com/reports/q3-2026', {
  headers: { Authorization: `Bearer ${process.env.INTERNAL_API_KEY}` },
});
const data = await apiRes.json();
// data = { period: "Q3 2026", revenue: 142300, mrr: 47400, users: 1820, ... }
2
Render data as HTML
report.js (continued)
function buildReportHtml(data) {
  const rows = data.line_items.map(item => `
    <tr>
      <td>${item.name}</td>
      <td>${item.category}</td>
      <td style="text-align:right">$${item.amount.toLocaleString()}</td>
    </tr>
  `).join('');

  return `<!DOCTYPE html>
<html>
<head>
  <meta charset="UTF-8">
  <style>
    body { font-family: 'Helvetica Neue', sans-serif; margin: 40px; color: #1a1a2e; }
    h1   { font-size: 28px; margin-bottom: 4px; }
    .period { color: #666; font-size: 14px; margin-bottom: 32px; }
    .kpi-row { display: flex; gap: 24px; margin-bottom: 32px; }
    .kpi { flex: 1; background: #f5f7ff; border-radius: 8px; padding: 16px 20px; }
    .kpi-label { font-size: 11px; text-transform: uppercase; letter-spacing: .06em; color: #888; }
    .kpi-value { font-size: 28px; font-weight: 700; color: #1a1a2e; }
    table { width: 100%; border-collapse: collapse; }
    th { background: #1a1a2e; color: #fff; padding: 10px 14px; text-align: left; font-size: 13px; }
    td { padding: 10px 14px; border-bottom: 1px solid #e8eaf0; font-size: 14px; }
    tr:nth-child(even) td { background: #f9faff; }
    @page { size: A4; margin: 20mm; }
  </style>
</head>
<body>
  <h1>${data.period} Revenue Report</h1>
  <p class="period">Generated ${new Date().toDateString()}</p>
  <div class="kpi-row">
    <div class="kpi"><div class="kpi-label">Revenue</div>
      <div class="kpi-value">$${data.revenue.toLocaleString()}</div></div>
    <div class="kpi"><div class="kpi-label">MRR</div>
      <div class="kpi-value">$${data.mrr.toLocaleString()}</div></div>
    <div class="kpi"><div class="kpi-label">Users</div>
      <div class="kpi-value">${data.users.toLocaleString()}</div></div>
  </div>
  <table>
    <thead><tr><th>Item</th><th>Category</th><th>Amount</th></tr></thead>
    <tbody>${rows}</tbody>
  </table>
</body>
</html>`;
}
3
POST to pdfsnap, receive PDF bytes
report.js (continued)
const html = buildReportHtml(data);

const pdfRes = await fetch('https://api.pdfsnap.dev/pdf', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${process.env.PDFSNAP_KEY}`,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    html,
    options: { format: 'A4', printBackground: true },
  }),
});

if (!pdfRes.ok) throw new Error(`pdfsnap error: ${pdfRes.status}`);

// Option A: save to disk
const fs = require('fs');
fs.writeFileSync('q3-report.pdf', Buffer.from(await pdfRes.arrayBuffer()));

Python: Django / Flask Integration

The same three-step pattern works identically in Python. Here's a Django view that fetches data and streams a PDF response to the browser:

views.py (Django)
import requests
from django.http import HttpResponse
from django.template.loader import render_to_string


def quarterly_report_pdf(request, period):
    # Step 1: fetch data from your internal API
    api = requests.get(
        f"https://api.example.com/reports/{period}",
        headers={"Authorization": f"Bearer {settings.INTERNAL_API_KEY}"},
        timeout=10,
    )
    api.raise_for_status()
    data = api.json()

    # Step 2: render HTML using a Django template
    html = render_to_string("reports/quarterly_pdf.html", {"data": data})

    # Step 3: convert to PDF via pdfsnap
    resp = requests.post(
        "https://api.pdfsnap.dev/pdf",
        headers={"Authorization": f"Bearer {settings.PDFSNAP_KEY}"},
        json={"html": html, "options": {"format": "A4", "printBackground": True}},
        timeout=30,
    )
    resp.raise_for_status()

    return HttpResponse(
        resp.content,
        content_type="application/pdf",
        headers={"Content-Disposition": f'attachment; filename="{period}-report.pdf"'},
    )

Scheduling Automated PDF Reports

For weekly or monthly reports that should land in an inbox automatically, run the pipeline on a schedule. In Node.js, a simple cron job with node-cron:

scheduler.js
const cron = require('node-cron');
const { generateAndEmailReport } = require('./report');

// Every Monday at 08:00
cron.schedule('0 8 * * 1', async () => {
  console.log('Running weekly report...');
  const period = currentWeekLabel(); // e.g. "2026-W37"
  const pdfBuffer = await generateReport(period);
  await emailReport(pdfBuffer, period);
  console.log(`Sent: ${period}`);
});

Storing PDFs: For audit trails or multi-party access, upload the PDF to Cloudflare R2 or AWS S3 after generation. Use a time-limited signed URL (15 min) in the email instead of attaching the binary. This keeps email size small and lets you revoke access if needed.

Performance Considerations

  • p50 latency is ~800ms for a single-page A4 PDF. For complex multi-page reports with charts, plan for 1.5–2.5s.
  • Parallel generation — pdfsnap handles concurrency on the API side. You can fire multiple report requests simultaneously without managing a browser pool yourself.
  • Caching — if the same report is requested multiple times (e.g., a dashboard "Export PDF" button hit repeatedly), cache the PDF bytes in Redis or object storage for 5 minutes to avoid redundant API calls.
  • HTML size — pdfsnap accepts up to 5MB of HTML per request. For reports with embedded base64 images (charts, logos), this is usually fine; for larger reports, link images via URL rather than embedding them inline.

Summary

Generating PDFs from API data doesn't require a browser binary in your deployment. The pattern is: fetch JSON, render HTML, POST to pdfsnap.

  • Build your HTML template once — it's just a string; use your language's template engine
  • Use printBackground: true and @page CSS for professional document output
  • Stream the response directly to the HTTP client or buffer it for storage/email
  • Schedule with any cron tool; the REST API is stateless and safe to call in parallel
